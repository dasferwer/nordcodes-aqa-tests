# Автотесты API управления сессиями

Java 17, JUnit 5, WireMock, Allure, Maven. Тесты отправляют HTTP-запросы в настоящее приложение; WireMock заменяет только внешний сервис.

## Результат проверки

Проверено 02.11.2026: **73 сценария, 64 успешных, 9 падений, 0 ошибок запуска, 0 пропусков**. Падения воспроизводят три дефекта: ограничение алфавита токена, HTTP 500 при неподдерживаемом методе и HTTP 500 при неподдерживаемом типе тела. Описание и шаги воспроизведения: [BUGS.md](BUGS.md).

Скачайте [report.html](report.html) и откройте его в браузере. Это автономный отчёт Allure: названия сценариев и шаги на русском языке, к запросам приложены фактические ответы. Красные проверки показывают расхождения с ожидаемым поведением. Вкладка Suites группирует проверки по назначению.

## Изолированный запуск

Нужен работающий Docker. JDK и Maven на компьютере не требуются. Получите JAR из материалов работодателя и выполните:

```sh
./run-isolated.sh /absolute/path/to/internal-0.0.1-SNAPSHOT.jar
```

Скрипт напечатает путь к новой папке результатов. Отчёт находится в `allure-report/index.html`, исходные результаты - в `allure-results/` и `surefire-reports/`. Можно передать вторым аргументом путь к новой папке результатов. Существующие результаты не перезаписываются.

При обнаружении дефектов команда возвращает ненулевой код, но сохраняет отчёт. Проверки не отключены и не помечены ожидаемо падающими.

При сборке скачиваются зависимости из Maven Central и официальный образ Maven. Сам JAR поступает в отдельный контейнер уже после сборки. Во время тестов интернет отключён (`--network none`); файловые папки компьютера и Docker socket не подключаются. Контейнер работает без root, без дополнительных capabilities, с файловой системой только для чтения и ограничениями CPU, памяти и числа процессов. Записывать можно в отдельный том результатов и временные каталоги. После копирования отчёта скрипт удаляет созданные им контейнеры и тома. Контейнерная изоляция не является доказательством безвредности неизвестного файла.

## Запуск в подготовленной среде

Если JAR уже проверен и используется отдельная тестовая среда с Java 17+ и Maven 3.9+:

```sh
mvn -B -ntp -Dapp.jar=/absolute/path/to/internal-0.0.1-SNAPSHOT.jar test
ALLURE_NO_ANALYTICS=true mvn -B -ntp allure:report
```

Вторую команду выполняйте отдельно, даже если тесты завершились с ошибкой. Она создаёт обычный отчёт в `target/site/allure-maven-plugin/`; для просмотра можно использовать `ALLURE_NO_ANALYTICS=true mvn allure:serve`.

Приложение и WireMock запускаются автоматически на свободных loopback-портах и останавливаются после класса тестов. Каждый сценарий получает отдельный токен; журнал и настройки внешнего сервиса сбрасываются перед сценарием. Встроенный `qazWSXedc` - демонстрационный ключ из задания, используемый только для локального приложения.

## Покрытие

| Группа | Сценарии | Проверок |
|---|---|---:|
| Сессия | Вход, действие, выход, повторный вход, несколько действий, независимость пользователей, внешние запросы и заголовки | 8 |
| Доступ | Отсутствующий, пустой, неверный ключ и другой регистр; отказ без изменения сессии | 15 |
| Входные данные | Допустимый алфавит, длина 31/32/33, отсутствие параметров, специальные символы, неизвестные действия, методы и типы тела | 26 |
| Внешний сервис | HTTP 200/201/202/204, произвольное тело, HTTP 4xx/5xx, разрыв соединения, таймаут и восстановление | 24 |

Проверяется результат операции, JSON-формат ответа и причина отказа, передача токена и заголовков, отсутствие внешних обращений для отклонённых запросов, сохранение или удаление сессии.

## Границы требований

Основные ожидания взяты из задания. Для успешного внешнего ответа используется стандартное понимание HTTP 2xx; текст причины ошибки не фиксируется. Для отказа в аутентификации допускаются 401 и 403. Методы и типы тела дополнительно проверяются на клиентский HTTP 4xx по [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html), без привязки тестов к конкретному коду. Эти проверки HTTP-протокола отмечены отдельно в BUGS.md.

ТЗ не определяет повторный LOGIN активного токена, LOGOUT неизвестного токена, перенаправления внешнего сервиса, дубли полей и конкурентные операции одного пользователя. Для них не закреплялись выдуманные бизнес-правила. Нагрузочное тестирование и полный аудит безопасности в объём не входят.
